# loopwatch v0.2 — Phase 0 revival notes

Date: 2026-09-25. Scope: the Phase 0 questions in [`PRD-v0.2.md`](PRD-v0.2.md) §8.

## Where each finding comes from

The session doing this work runs in a cloud container linked to Marcus's Mac. The Mac's `~/.claude` and
`~/Library/Application Support/Claude` are protected locations that a linked session cannot open. So the
findings come from two places:

1. **Verified here**, by experiment against Claude Code **2.1.283**, the same CLI loopwatch drives.
2. **Mac-only questions.** These are answered by running `bin/loopwatch-discover.sh` on the Mac. It is read-only, hashes project names, and never prints message content. Paste its output below the line at the end of this file.

## Verified findings

### Bug 1 (self-ingestion): confirmed
I ran `claude -p "Reply with exactly: ok" --model haiku --output-format json` from a fresh `/tmp/lwprobe`. It
created `~/.claude/projects/-tmp-lwprobe/<session>.jsonl`, **231 KB for a one-word answer**, because the
persisted transcript carries the whole prompt context. With v0.1's default glob, the next night would have
re-mined that file. Every run would ingest the previous run's bundle, and the cost would compound.

I repeated the run with `--no-session-persistence`. **No project dir was created.** v0.2 fixes the bug three ways:
- It passes `--no-session-persistence` whenever `--help` lists it.
- It always runs from a fixed directory, `~/.local/state/loopwatch/run`, and excludes that directory's encoded project dir from collection.
- It drops any transcript line whose `cwd` field is the run directory.

### Project-dir encoding
`/tmp/lwprobe` became `-tmp-lwprobe`, and `/home/claude/loopwatch` became `-home-claude-loopwatch`. Every
non-alphanumeric character becomes `-`. v0.2 derives the excluded dir name with the same rule and also
excludes any dir whose name ends in `-loopwatch-run`, in case symlinks resolve differently (`/private/var` on macOS).

### CLI capabilities (2.1.283)
| Flag | Status | Used for |
|---|---|---|
| `--output-format json` | works | Returns `total_cost_usd`, `usage.{input_tokens,cache_read_input_tokens,cache_creation_input_tokens,output_tokens}`, `duration_ms`, `num_turns`, `is_error`, `subtype`, `result`, and `modelUsage.<model>.costUSD`. This feeds the ledger (R-12) |
| `--max-budget-usd` | works, **enforced** | Native spend cap (R-1). A 0.05 cap on a Haiku call that cost 0.066 returned `is_error:true` with exit 1 |
| `--no-session-persistence` | works | R-4 |
| `--max-turns` | accepted, but **not listed** in `--help` | Passed only when `--help` lists it or `PASS_MAX_TURNS=true` |
| `--strict-mcp-config` | works | Keeps the user's MCP servers out of headless runs, for cost and blast radius |

**Fixed overhead:** a trivial Haiku `-p` call cost **$0.013–0.018**, most of it system-prompt cache creation.
That per-call floor is why R-2 (skip with zero calls) and R-3 (no Stage B on empty triage) matter.

### Transcript schema (Claude Code 2.1.x)
Line `type`s seen: `user`, `assistant`, `attachment`, `mode`, `last-prompt`, `atis-latch`, `queue-operation`.
The fields that matter to the filter:
- `isMeta: true` marks harness-injected user text, such as `<system-reminder>` blocks. **Drop these.**
- `isSidechain: true` marks subagent traffic. **Drop these** (it duplicates what the parent summarizes).
- `cwd` is on every line. It is the second self-ingestion guard.
- `message.content` is either a string or an array of `{type: text|tool_use|tool_result|thinking}`. Only `text` is kept.
- Inline `<system-reminder>…</system-reminder>` blocks inside user strings are stripped.

Phase 1 adds a trimmed, synthetic fixture of this shape (`test/fixtures/claude-code-2.1.jsonl`).
