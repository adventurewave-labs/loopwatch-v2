[user] The nightly loop keeps getting more expensive every day even though I barely worked. Figure out why.
[assistant] [tool:Bash] ls ~/.claude/projects | grep -i tmp
[assistant] Found it. Every headless run of claude -p persists its own session under ~/.claude/projects/<encoded cwd>/. The loop runs from $TMPDIR/loopwatch.XXXXXX, so each night writes a new project dir like -private-var-folders-...-T-loopwatch-a1B2c3 containing the ENTIRE bundle it was fed (a 1-word test answer produced a 231 KB transcript). The collector glob ~/.claude/projects/*/*.jsonl then picks that up the next night, so night N+1 re-ingests night N's input: cost compounds and old content is re-mined.
[user] What's the fix? I want it robust even if the CLI changes.
[assistant] Three layers. (1) Pass --no-session-persistence (verified on claude 2.1.283: no project dir is created). (2) Always run from a FIXED directory, ~/.local/state/loopwatch/run, and exclude its encoded project dir (every non-alphanumeric char becomes '-') plus anything ending in -loopwatch-run, and v0.1's loopwatch-XXXXXX mktemp dirs. (3) Drop any transcript line whose cwd field equals the run dir, which catches a moved or renamed project dir. Tradeoff: (2) means a fixed run dir, so runs must be serialized. The existing mkdir lock already does that. Gotcha: on macOS /var is a symlink to /private/var, so the encoded name can differ from what you compute. That's why the suffix match exists.
[assistant] [tool:Bash] claude -p 'Reply with exactly: ok' --model haiku --output-format json --no-session-persistence
[assistant] Confirmed: with --no-session-persistence no project dir appears. Also learned --max-budget-usd is enforced: a 0.05 cap on a call that cost 0.066 returned is_error:true, exit 1. So a budget hit must be treated as a fail-closed outcome that keeps watermarks, or the same delta just burns again. Decision: budget hit = failed run, watermarks held, ledger row with skipped_reason=budget_exceeded.
